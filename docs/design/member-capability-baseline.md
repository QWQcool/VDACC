# 会员资源可用性基线（B站 / 网易云）

状态：**2026-10-30 实测**，使用用户本人已登录的账号（本项目自己的 profile，
凭据在 `%LOCALAPPDATA%\vdl\auth\`，未读取任何浏览器或手机 App 的登录态）。
只记录「平台是否把地址给出来」和档位元数据，不记录内容本身。

## 0. 边界（先说清楚）

- 本文是**能力核对**：用你自己已付费的账号，问平台「这个账号能拿到哪些档位」，如实记录。
- **没有**做任何伪造凭证、盗用 cookie、破解 DRM 或绕过付费墙的实现；也没有这类计划。
- 手机 App 里的登录态不可用于本工具（那是你设备上别的应用的凭据，既读不到也不该读），
  端上仍然没有登录能力——这不是「被封」，是产品边界。
- 结论只对「此刻这两个账号」成立，不能推广成「平台支持下载」。

## 1. 账号状态

| 平台 | 账号 | 会员标识 | 含义 |
|---|---|---|---|
| B站 | 晨星成焰 | `isLogin=true`、`vipStatus=1`、`vipType=2`、Lv6 | 大会员生效（`vipStatus=1`） |
| 网易云 | 晨星成焰 | `vipType=110` | 黑胶会员 |

## 2. 网易云：会员 vs 匿名

同一首歌、同一个 `br=999000` 请求，只差 Cookie：

| 曲目 | 会员 | 匿名 |
|---|---|---|
| 我不难过（fee=1，孙燕姿） | `code=200`、`type=flac`、`br=901303`、36.1 MB | `code=-110`、无地址 |
| 天龙八部之宿敌（fee=1，许嵩） | `code=200`、`type=flac`、`br=1546095`、50.9 MB | `code=-110`、无地址 |
| 甲乙丙丁（fee=1，李佳薇） | `code=200`、`type=flac`、`br=1656112`、43.6 MB | `code=-110`、无地址 |
| 雨爱(钢琴版)（免费曲） | `type=flac`、`br=476590`、15.3 MB | 只有 320K mp3（10.3 MB） |

**另一个必须记住的反面证据**：`id=186016` 在会员状态下四档仍然全 `code=404`、
`formats` 为空、报 `filtered`。也就是说**「有会员」不等于「这首歌可下」**——
可能是下架、版权到期或按单曲售卖。工具如实报告，不做「再试别的接口」的绕过。

## 3. B站：会员 vs 匿名

**普通投稿**（`BV1SknF6KE5g`，原生 1080P）：

| 身份 | 档位 |
|---|---|
| 会员（桌面） | `bili-1920 1080P`（124.9 MB）、`bili-1280 720P`、`bili-sd 852×480` |
| 匿名（手机实测） | 仅 `bili-sd 852×480` |

**番剧**（`ss33378` 第 1 集，`ep_id=321808`，大会员区）：

| 身份 | 视频轨 | 最大宽度 | 清晰度 id | 音频轨 |
|---|---|---|---|---|
| 会员 | 16 条 | 1440 | `125,112,80,64,32,16`（含 1080P+/高帧率/HDR） | 3 |
| 匿名 | 6 条 | 640 | `32,16`（仅低清/试看级） | 3 |

两侧 `code` 都是 0——差别不在「接口拒绝」，而在**给出的轨不一样**。
这类差别不会被 UI 的「未登录」提示说清楚，必须比对轨数量才看得出来。

## 3.5 端上登录之后（2026-10-30 晚，同两个账号）

手机端加了登录（独立 WebView，cookie 不出原生）之后，同一批链接在**手机上**复测：

| 场景 | 匿名（登录前） | 登录后（大会员 / 黑胶） |
|---|---|---|
| B站 `BV1SknF6KE5g` 档位 | 只有 `852×480` | **1080P 119.08 MB** / 720P 40.67 MB / 852×480 24.05 MB |
| 网易云 `287398`（fee=1） | `need_login`，无档位 | **无损 FLAC 34.42 MB** / 320K 12.23 MB / 128K 4.89 MB |
| 网易云 `2007983648`（免费曲） | 只给 320K mp3 | **真无损 FLAC 15.3 MB / 477 kbps**，标签+600×600 封面正常 |
| 网易云 `186016` | `code=404` | **仍然 `code=404`**（会员也不放行，见 §2） |

端上实测落盘：`287398_我不难过_无损 FLAC.flac` 36,097,193 字节（`ffprobe`：`901303 bps`、
320.4 s、`ffmpeg -f null` 解码通过）；免费曲那份 15,363,786 字节，`TITLE/ARTIST/ALBUM` +
`mjpeg 600x600` 齐全。

账号区状态显示为「在线有效 · 晨星成焰（大会员）」「在线有效 · 晨星成焰（黑胶）」——
端上用接口真问了一次（B站 `nav` / 网易云 `nuser/account/get`），不是只看 cookie 在不在。

## 4. 顺带修掉的一个真 bug

会员数据暴露出上一版「如实标注」的误判：网易云**真无损**时接口给的 `br` 是 FLAC
编码后的实际码率（实测 476590 / 901303 / 1546095），而旧逻辑拿它跟请求档位 999000 比，
于是把真无损标成「477K（可能没有该档权益）」。现在判据改为：**无损档看 `type` 是不是 `flac`**，
其它档才比码率。桌面端加了对应用例（N0c），测试 155 → **156 pass**。

## 4.5 登录暴露出来的三个真 bug（都已修）

1. **漏 import 变成「点击无反应」**：`netease.ts` 里用了 `loggedIn()` 却没 import，运行时抛
   `ReferenceError`；真机上表现为「粘链接后点解析完全没反应」，既没结果也没报错。
   教训：端上没有 console 转发时，一个 typo 就是「无声失败」——顺手给 WebView 接上了
   `onConsoleMessage` → logcat（tag `VDACC-Console`），以后这类错误能看到。
2. **`head.truncated` 误判导致整曲 FLAC 不写标签**：`readHead` 只读前 512 KB，
   `head.truncated && ext === 'flac'` 对**任何**大于 512 KB 的 flac 都成立，于是真实整曲无损
   全被跳过写标签（36 MB 的会员曲 `format_tags` 为空，而 104 KB 的探针样本恰好通过）。
   现在把「块链是否读完」交给 `buildFlacTag` 自己判断。
3. **四档串行导致解析十几秒**：登录后四档都有地址，串行就是 4 次 API + 4 次 HEAD。
   改成两波并行（先并发问四档，再并发 HEAD），并把 HEAD 超时从 10 s 降到 6 s
   （拿不到就退回接口声明的 size）。

## 5. 未覆盖

| 项 | 原因 |
|---|---|
| QQ 音乐 / 酷我 / 酷狗 的会员档 | 用户只有 B站与网易云会员；本地 QQ 凭据也已失效 |
| 付费单曲（非会员库） | 本次样本里没有确认可按单曲购买的曲目 |
| 地区限制 / 下架判定 | 接口只给一个 code，无法区分「下架」「地区」「按单曲售卖」——不猜 |
| 番剧 DRM / 加密轨 | 未做任何解密尝试；只记录平台给出的轨数量与清晰度 |
| 端上使用这些档位 | 手机端没有登录能力（`need_login`），本期不改 |

## 6. 下一步可做的事（都不涉及绕过）

1. **端上登录**：把 `auth` 搬进 App（系统浏览器授权 + 自建 profile），让会员档位在手机上也可用。
   工作量远大于「加个输入框」，且要处理 cookie 保存与失效。
2. **把「会员/匿名」能力矩阵变成回归**：同一批样本定期跑，平台改了档位规则能第一时间发现。
3. **番剧试看识别**：这次样本两侧 `code=0`、`is_preview` 都为空，说明「试看」不是靠这个字段
   表达的；要在 UI 上区分「整集」与「片段」，得另找证据（例如时长与轨数量对比）。
