# 风格迁移计划：从已下载视频反推提示词，再用 MiniMax H3 生成

> 状态：**已冻结（2026-11-02）**，未开工。重启条件见 §0.1。
> 本文取代 `Plan.md` 里原先「目标 C 已暂缓」的结论——方向成立，但范围比当初窄：
> **只做「同风格新内容」，不做人物三视图，也不追求逐镜头复刻。**

## 0.1 冻结原因与重启条件（2026-11-02）

解冻当天就发现绕不过去的一步：**拿不到 H3 的运行通道**。用户原先靠租算力服务器跑 H3，
现在不再长期租；本机是 RTX 3080（**10 GB 显存**），够跑 480–512p/2–5 秒的无声小模型做管线联调，
但 H3 的定位是 768P / 4–15 秒 / **原生音频同一次推理** / 2K regeneration，**差一个数量级**，
不能用小模型替它验收——提示词的有效性是模型特有的，换个模型测出来的"能出片"不能外推。

于是 A0 的第三项（H3 手动出片）与 A5（生成评估）**无法关闭**：

| 阶段 | 冻结影响 |
|---|---|
| A0 | 前两项（DeepSeek 连通、抽帧质量）可以做，第三项做不了 → A0 无法整体通过 |
| A1–A3 | 技术上不依赖 H3，但缺了 A5 的闭环，做出来无法判断对错，等于攒技术债 |
| A4 | 只能校验「三字段齐全 / 时长合规」，无法证明"喂给 H3 会得到像的画面" |
| A5 | **完全阻塞** |

**重启条件**（满足任一条即可解冻）：

1. 有 H3 的可用通道：官方 playground 额度，或按小时租一张 24–48 GB 的卡（A0 一次 + A5 五条样本，约 15 次出片，**几小时、几十元**量级，不需要长期租）；
2. 或者把范围再收窄成**纯分析**（只做 A1：分镜 + 台词 + 客观指标），绕开一切生成模型——但要先想清楚它作为独立功能的产品入口在哪，否则只是个命令行分析器。

**注意**：不要因为本文存在就把 A0–A5 当成待办。冻结期间的开发主线见 `Plan.md` §2.6。

## 0. 一句话目标

给一条已经下载好的视频 → 输出一张**风格卡** + 一组**可直接喂给 MiniMax H3 的提示词** →
生成一条「风格像、内容新」的视频。

## 1. 已定参数

| 项 | 定值 | 影响 |
|---|---|---|
| 视频生成模型 | **MiniMax H3**（开源权重，2K） | 提示词必须按 H3 官方三字段格式写，见 §3 |
| 视觉理解模型 | **DeepSeek**（用户确认支持图像输入） | 抽帧后逐镜描述；开工第一步先验证连通性 |
| 目标 | **同风格、新内容** | 只需要风格卡，不需要精确复刻运镜序列 |
| 参考实现 | **bradautomates/claude-video** | 借鉴帧预算、去重、字幕优先三件事 |

## 2. 边界（先划清楚，避免越做越大）

**做**：分镜切分、抽帧、转写、逐镜结构化描述、风格归纳、H3 提示词生成、生成结果的代理指标评估。

**不做**：
- **人物三视图**——跨视角一致性仍是行业难题，做了也只能到「参考级」，不值得排期。
- **逐镜头复刻**——用户明确要「同风格新内容」。
- **训练/微调**——全部走 API 推理，不做 LoRA。
- **判断生成结果「好不好看」**——只做「像不像原片风格」的代理指标 + 人评，不做美学评分。

## 3. MiniMax H3 的硬约束（写模板前必须遵守）

H3 的提示词**不是随便一段自然语言**，官方 guide 规定了结构：

```
integrated_multimodal_description: [Shot 1] ...（视觉、动作、镜头、说话人、对白、画内音，沿时间线）
overall_soundscape: ...（环境声、物理动作声、非语言人声）
non_diegetic_music: ...（角色听不到、只有观众听到的背景音乐）
```

要点：

- **三个字段缺一不可**，纯文本生成（T2VA）时直接从这三个字段开始，不需要额外的 instruction 行。
- 用了首帧/尾帧（I2VA / FL2VA / L2VA）才需要在最前面加 instruction，例如 I2VA 固定写法：
  `For the target video, at 0.00 seconds into the target video, (from [Shot 1]) is fully referenced.`
- **时长 4–15 秒**：一条提示词对应 4–15 秒的连续片段，超了要拆。
- **原生 32kHz 立体声音频**，同一次推理产出，所以声音必须写进提示词，不能指望后期补。
- **2K 不是超分**，是 768P 结果的 in-context regeneration。生产上建议先 768P 验证，再决定要不要 2K。
- 社区经验：**导演型提示词优于描述型**——一个主体动作 + 一次镜头运动；用时间码分块；
  显式声明「什么不能变」；负面指令（"no soft dissolves"）比正面描述更有效。

## 4. 核心设计决策：能算的不要问模型

风格卡里有一半字段是**能用 ffmpeg 直接量出来**的，这部分不该花钱问 VLM，也不该让它猜：

| 字段 | 来源 | 方法 |
|---|---|---|
| 平均镜长 / 镜头数 | **ffmpeg 直算** | `scdet` 场景切换检测 |
| 饱和度 / 对比度 / 亮度分布 | **ffmpeg 直算** | `signalstats` |
| 主色调 | **ffmpeg 直算** | 抽帧后统计直方图（k-means 取前 3 色） |
| 颗粒强度 | **ffmpeg 直算** | 高频残差能量估算 |
| 响度 / 动态范围 | **ffmpeg 直算** | `ebur128` |
| 内容、情绪、构图意图、风格命名 | **VLM** | 只有这些需要语义理解 |

这条分界让风格卡既便宜又更准：`avg_shot_length = 2.3s` 是量出来的，不是模型猜的。

## 5. 风格卡字段（v1 草案）

```json
{
  "schema": 1,
  "source": {"path": "...", "duration_s": 23.6, "shots": 11},
  "measured": {
    "avg_shot_s": 2.15,
    "saturation": 0.32,
    "contrast": 0.41,
    "luma_mean": 0.47,
    "grain": 0.18,
    "loudness_lufs": -16.2,
    "palette": ["#2b3a45", "#c8b49a", "#e8e2d6"]
  },
  "inferred": {
    "lighting": "自然光为主，高调柔光，逆光占比高",
    "lens": "中长焦压缩感，浅景深",
    "camera": ["static", "slow push"],
    "editing": "硬切为主，节奏偏慢",
    "texture": "细颗粒，低饱和，轻微偏青",
    "subject": "青年人物，日常服装，室内/街景",
    "mood": "克制、安静、略带怀旧",
    "genre_tags": ["日系", "生活流"]
  },
  "prompt_hints": {
    "must_keep": ["低饱和青调", "自然光", "硬切"],
    "avoid": ["炫光", "快速运镜", "高饱和"]
  }
}
```

`measured` 与 `inferred` 分开存，是为了将来能替换任一侧而不影响另一侧。

## 6. 阶段计划

| 阶段 | 内容 | 产出 | 验收 | 估时 |
|---|---|---|---|---|
| **A0 预检** | 验证 DeepSeek 图像输入连通、抽帧质量、H3 手动跑通一次 | 一份连通性记录 + 1 条手写 H3 提示词的生成结果 | DeepSeek 能对一张 1080×1440 帧返回结构化 JSON；H3 能出片 | 0.5d |
| **A1 分镜与素材** | `scdet` 切分、帧预算、去重、字幕优先/Whisper 兜底、`signalstats` 指标 | `scenes[] + frames[] + transcript + measured` | 30s 视频：帧时间戳与 ffprobe 误差 <0.1s；镜长与肉眼一致 | 1d |
| **A2 逐镜描述** | DeepSeek 逐镜结构化描述（景别/主体/动作/光线/构图） | 每镜一份 JSON | 字段齐全率 100%；人工抽查 10 镜无事实错误 | 1d |
| **A3 风格卡归纳** | `measured` 直算 + `inferred` 由 VLM 跨镜归纳 + 人工校正 | `styleCard.json` | `measured` 与 ffmpeg 直算逐项一致；风格标签人工可接受 | 1d |
| **A4 H3 提示词** | 风格卡 + 新内容 brief → H3 三字段提示词 | 可直接粘进 H3 的 prompt 文本 | 格式合规（三字段齐全）、H3 不报错、时长 4–15s | 1d |
| **A5 生成与评估** | 跑 5 条不同风格样本，做代理指标 + 人评 | 评估报告 | ≥3/5 条人评 ≥3 分；代理指标与原文差异在阈值内 | 1d |

合计约 **6 个工作日**。A1 独立可用——就算后面几段停掉，「分镜 + 台词 + 客观指标」本身就有价值。

## 7. 代码落点

```
ts/src/analyze/
  scenes.ts      分镜切分（ffmpeg scdet）
  frames.ts      帧预算 + 抽取 + 去重（借鉴 claude-video：<30s→30 帧，>10min→100 帧封顶）
  transcript.ts  字幕优先，Whisper 兜底
  metrics.ts     ffmpeg 直算的客观指标
  vlm.ts         DeepSeek 客户端（图像输入，retry/限速）
  describe.ts    单镜结构化描述
  stylecard.ts   风格卡归纳
  h3.ts          H3 三字段提示词生成
ts/tests/analyze.test.ts
```

CLI：

```bash
bun ts/src/cli.ts analyze "<本地文件或链接>" --json          # 分镜 + 风格卡
bun ts/src/cli.ts analyze "<文件>" --frames-only             # 只出帧，省 API 钱
bun ts/src/cli.ts brief styleCard.json --brief "便利店夜戏，两个人" --json   # 出 H3 提示词
```

约定：
- **不新增 npm 依赖**。抽帧走 ffmpeg 子进程，VLM 走 `fetch`。
- API key 只从 `DEEPSEEK_API_KEY` 读，不落盘、不打印、不进日志。
- 分析产物默认写到 `下载/_analysis/<视频ID>/`（已被 `.gitignore` 覆盖）。
- 单镜描述与风格卡都带 `schema` 字段，便于以后演进。

## 8. 风险评估

| 风险 | 影响 | 应对 |
|---|---|---|
| DeepSeek 图像输入的实际能力未验证 | A2 全阻塞 | A0 第一件事就测；不行就换云端 VLM（Qwen-VL / GLM-4V） |
| 「风格」被模型说成「内容」 | 生成结果只像内容不像风格 | 提示词强制覆盖光线/焦段/色调/颗粒四维，`measured` 提供硬数字 |
| H3 对中文提示词的响应未知 | 提示词模板要返工 | A0 用中英各一版对比，先定语言再写模板 |
| 一条视频风格不统一 | 风格卡失真 | 先按场景聚类，风格差异大就分卡（多段视频各出一张） |
| 生成结果无法客观评判 | 无法验收 | 代理指标（直方图距离/镜长差/饱和度差）+ 人评双轨 |

## 9. 参考：claude-video 值得抄的三件事

`bradautomates/claude-video`（MIT，17.4k stars）解决的是「让 Claude 看视频」，链路是：
yt-dlp 查字幕 → 只下需要的部分 → ffmpeg 抽帧 → 带时间戳的转写 + 帧一起给模型。

抄三条：

1. **帧预算随片长缩放**：<30s 约 30 帧，>10min 封顶 100 帧——不是均匀抽满。
2. **送模型前去重**：近似帧先丢掉，省 token 也减少重复描述。
3. **字幕优先**：有现成字幕就用，没有才调 Whisper（它用 Groq `whisper-large-v3` 为主、`whisper-1` 兜底）。

不抄的部分：它的 `/watch` 是问答式，没有「归纳风格」这一步；也不产出生成模型的提示词。
